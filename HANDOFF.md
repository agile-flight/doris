## For Agent A: open findings from the adversarial review, most severe first
Do these as slices (tests first). Reproduction scripts existed only in a temp dir; rebuild each repro as a test.
1. `api.py`: `bool("false")` is True. Reject non-boolean `vendor_confirmed` / `approve` with 400. (Wrong PAY + poisons the record.)
2. `pipeline.resolve_callback`: `called` is never checked against `callback_number` on file; a confirmation from any number is accepted. Reject mismatches.
3. Follow-up state: a CALLBACK can be resolved twice; `resolve_review` accepts any decision, including a prompt-injection BLOCKED. Refuse superseded decisions; only HOLD takes a review; a confirmed callback with no `bank_account_new` must not PAY.
4. `ingest.near_white` only catches TypeError; a pattern colour raises ValueError and drops the whole PDF as `error`, which nothing reads. Treat an unreadable attachment as a HOLD reason.
5. `judge.py`: the prompt_injection signal's `detail` quotes hidden text, so it reaches the judge prompt. Pass hidden text as a count/kind only.
6. HTML hidden-text regex: `background-color:#ffffff`, `font-size:1.2em`, `color:#fff000` are false positives (BLOCKED); `<br>` inside a hidden span hides everything after it. Anchor the regex (`(?<![-\w])color`, exact `font-size:0`), handle void tags.
7. HTML misses: `</b>` inside `display:none` pops the frame (pops ignore tag names); class CSS in `<style>`; `font-size:2px`; `color:#fefefe`; `<font color=#ffffff>`; `position:absolute;left:-9999px`; `opacity:0.0`.
8. When text/plain exists the HTML part's visible text is discarded; a bank change only in the HTML is missed. Scan both parts.
9. PDF: render-mode-3 text, white text sharing a line with visible text (<80% rule), and separation colours are misread. Classify per character, not per line.
10. Only the first account number across attachments counts; HTML attachments and `application/octet-stream` PDFs are ignored. `ExtractedInvoice.other_account_last4` already exists for this.
11. `bank_change`: only last-4 compared, routing never compared. `VendorOnFile.routing_last4` exists; store and compare routing too.
12. A forged "Forwarded message" block replaces the real sender. Keep `outer_sender_email` (field exists) and run the lookalike check on both.
13. `ct_domain`: certificate age uses the message's own Date header. Use `ctx.now` (data on file / our clock), never the message.
14. `vendors`: edits to `domain`/`bank_last4` never raise the score; a first-time phone (`versions[1:]`) is skipped; `update_field(at=200 days ago)` is trusted immediately. Trust from `recorded_at`, and treat any post-creation version as a change.
15. Claude's extraction is not validated: a full account number or `****8841` as last4 breaks the schema; currency `$`; negative amounts. Normalise to 4 digits / ISO code / >= 0 in `extract()`.
16. `llm.py`: a truncated or refusal response raises `pydantic.ValidationError` (not an AnthropicError) and escapes; missing credentials raise TypeError. Catch both and degrade to offline.
17. Schema breaks from stored data: non-E.164 phone on file (now filtered by `trusted_phone`, still worth validating in `VendorStore.create`); `POST /check {"invoice_id": 42}` stores an int.
18. `api.py`: `do_GET` has no try; `limit=abc`, bad Content-Length, `{"text":123}`, `called:5`, unknown charset give 500 or no response. Wrap and return 400.
19. Fixed: the audit `kind` column is sealed into the hash.
20. `amount_anomaly` alone (0.12) can never reach HOLD; a $10^23 invoice pays. Add an absolute-amount gate (e.g. > 3x max history → HOLD).
Then: a third teammate builds the DOJ-derived test set against `detector/testset/cases.json`'s format.

## Calls made that interpret the build doc
- A bank change with a number on file 90+ days is always `CALLBACK`, even at a high score; the call is the verification and the best evidence. Only prompt injection blocks outright (score floored at 0.95).
- Caught means money did not move (BLOCKED, CALLBACK or HOLD). For legitimate invoices the matrix separates blocked outright (real error) from held/called (by design).
- Email bodies are never stored: the chain holds an intake record (hashes, attachment names) then the Decision.
- Samples are generated offline, so `llm_judgment` shows `skipped` in them.
