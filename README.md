# Doris

An accounts-payable agent that stops vendor-impersonation fraud (the "we changed our bank
account" scam) before money leaves, then verifies by calling the vendor at the number already
on file. *Doris only trusts what's on file.*

This repository is split at one seam, the **Decision** object (`contract/`):

| Folder | Owner | What it is |
|---|---|---|
| `detector/` | Agent A | Email + PDF in, Decision out: extraction, eight deterministic checks, Claude's judgment, risk score, versioned vendor records, hash-chained audit log, HTTP API, confusion matrix. |
| `surfaces/` | Agent B | Review screen with the CT timeline, the callback (Cartesia voice over Twilio), the forward-to-check door, the BLOCKED screen. |
| `contract/` | both | `decision.schema.json` (frozen), `README.md` (field meanings, decision rules, hash formula, API), `samples/` generated by the pipeline, `check.sh` (the contract test). |
| `coord/` | both | Mailbox between the two agents: `from_A.md`, `from_B.md`. |

## Run it

```bash
uv venv --python 3.13 .venv && uv pip install --python .venv/bin/python -e ".[dev]"
.venv/bin/pytest -q                       # everything (contract + detector), offline, no network
.venv/bin/python -m detector --offline check detector/fixtures/emails/bank_change_lookalike.eml
.venv/bin/python -m detector serve        # API on http://127.0.0.1:8787 for the surfaces
.venv/bin/python -m detector evaluate     # confusion matrix: catch rate AND false-positive rate
.venv/bin/python -m detector samples      # regenerate contract/samples from the pipeline
```

With `ANTHROPIC_API_KEY` set (or an `ant auth login` profile), extraction and the residual
judgment run on `claude-opus-5-5` through structured outputs, with server-side refusal
fallbacks enabled. Without credentials, or with `DORIS_OFFLINE=1`, the deterministic path runs
alone: the regex extractor, the eight checks, the score, the chain. Tests always run offline.

## How a decision is made

1. **Ingest** (`detector/ingest.py`): `.eml` or forwarded text; PDF text is split into visible
   text and hidden spans (white, tiny, off-page, CSS-hidden) with line numbers.
2. **Extract** (`detector/extract.py`): payee, amount, invoice number, account last-4, whether a
   bank or contact change is requested, urgency phrases. Claude sees visible text only.
3. **Match the record on file** (`detector/vendors.py`): exact domain, then claimed name, then
   payee, so a lookalike still gets compared against the real vendor.
4. **Checks** (`detector/checks/`): bank account changed, prompt injection, vendor contact changed
   in the last 90 days, payee mismatch, lookalike domain, newly certificated domain (crt.sh),
   amount anomaly, urgency, plus the new-vendor gate.
5. **Judgment** (`detector/judge.py`): Claude scores the residual narrative risk.
6. **Score and decide** (`detector/scoring.py`): noisy-OR over tier weights; rules in
   `contract/README.md`. A bank change with a number on file for 90+ days is always `CALLBACK`.
7. **Seal** (`detector/audit.py`): the Decision becomes a record in the hash chain and lands in
   `data/outbox/`. Callback results and human reviews are superseding Decisions in the same chain.
